## [Unreleased]

### Added

- About state (`states/AboutState.tsx`): the About corner now opens a real full-screen founder statement instead of the noise-register placeholder. Removed the dead scroll-era `sections/About.tsx` and its exclusively-used `.lab-card-surface` styles (both themes) now that the state replaces it. A split editorial composition inside the no-scroll shell — eyebrow, title, and lead anchor the left column; the two founder paragraphs, a `RICARDO LAMADRID` signature, and a quiet **Contact bridge** sit on the right. The bridge mirrors the hero's Work hand-off: it fires the field pulse toward the bottom-right corner (`fireCornerActivation("br")`) as About morphs into Contact, so the corner nav and the in-content action read as one system. On-mount stagger reveal (matching Work's entrance, not a scroll reveal — the shell never scrolls); stacks to a single column on mobile; `prefers-reduced-motion` opts out of the stagger and rise. Signal scarcity holds — the accent lives only on the eyebrow dot and the Contact bridge on hover. `ShellStage` routes `about` here; `contact` stays a placeholder. Reuses the existing `about` dictionary content (EN/ES/FR).
- Context-aware field, part 1 — the nav reaches into the field (Signal / Noise pointer, slice 3): hovering or keyboard-focusing a corner now **leans the field's ambient static toward it** and brightens it, weighted by proximity and eased in/out (a `CornerPull` in `src/lib/pointer-field.ts`), on both the hero and Work fields; and activating a corner (or the hero CTA) **throws the signal pulse from the field center toward that corner** as the state hands off (`Pulse` gained a direction; `firePulse(..., toward?)`). A new DOM-free `src/lib/shell-signal.ts` bus carries the hovered/activated corner from the React nav into the framework-free field loops (they subscribe to wake and read it each tick), so React never enters the animation path. Glyph fragments stay exempt so the headline holds; touch and `prefers-reduced-motion` are unaffected.
- Context-aware field, part 2 — the Work index resolves out of the field (Signal / Noise pointer, slice 3): the field is now **attracted to the selected project, then resolves behind it into signal**. A `RowBand` (`pointer-field.ts`) anchors a contained horizontal band on the selected row — a skirt drifts nearby static inward while the core aligns it horizontal, brightens it, and lets the brightest center reach the accent — and the band's center **eases between rows** so changing selection morphs the field rather than cutting. A `src/lib/work-signal.ts` bus carries the selected row's target from the index to the field loop. Entering Work also reveals the rows once with a fast stagger, and the active row grows a thin signal tick tying the resolved band to the DOM. Touch taps drive it; reduced motion stays calm.
- Signal pulse on interaction (Signal / Noise pointer, slice 2): `pointerdown` now fires a non-generic burst from the signal engine (`Pulse` in `src/lib/pointer-signal.ts`) — nearby signal first **compresses** inward toward the core (a fast rush that momentarily silences the field), then **releases** outward as a geometric transmission: an expanding, deliberately *open* Dynamic-Frame corner square, a cross-shaped scan sweeping just ahead of it, and a 7-node constellation that spreads and thins with connector lines. No circular ripple. Fires in ~700ms and recycles a single pooled object (a rapid double-click restarts rather than stacking); size and brightness scale with the detector's energy at the moment of the click, and peak-energy clicks tip the nodes into the acid accent. Primary pointer only; wired into `HeroField`'s existing loop, which now also idles on pulse completion. Not attached under `prefers-reduced-motion` (no listeners run there), so reduced-motion users get no burst.
- Signal layer — velocity-driven pointer foreground (Signal / Noise pointer, slice 1): a new DOM-free engine (`src/lib/pointer-signal.ts`) that adds the two things the existing positional field lacked — motion identity and a wake. A `PointerMotion` tracker turns raw pointer events into a smoothed detector position, velocity, heading, and a single `energy` value (`clamp01(speed / SPEED_REF)`) that drives the whole layer; nothing is attached to raw event coordinates. On top of it: a **signal core** (a crisp 1–2px detector that stretches along the heading and brightens with speed, shows a faint coordinate cross at rest, and sparks acid `--lab-energy` only at peak speed) and a **directional transmission trail** (a pooled, non-allocating wake of broken signal lines, bright nodes, and tiny data-rect fragments that sample tighter and live longer the faster the pointer moves, 0.45–0.9s, with a very low-alpha red/cyan channel split on high-energy marks only). `HeroField` drives the new layer in the same rAF loop above the field and keeps idling once field, motion, and trail have all settled; `prefers-reduced-motion` still renders one static frame with no core or trail. New `--lab-energy` acid token (both themes), reserved for the pointer layer's rare high-velocity peaks.
- Centered hero composition — the hero headline, lead, and CTA now center on the axis instead of left-aligning.
- Project micro-universes (living-interface project mode): selecting a project no longer navigates, opens a tab, or routes to a case-study page — the Signal / Noise world **reorganizes in place into that project's immersive micro-universe** as an in-app mode, and "back" morphs it back to the Work index. `ShellProvider` gains `activeProject` with `openProject`/`closeProject`; `ShellStage` layers a scale-fade `ProjectWorld` over the still-mounted index (reduced motion cuts), and takes the underlying state `inert` while a world is open so keyboard/AT users can't reach the occluded index.
- Work index as a full-screen state (`states/WorkState.tsx` + `work/WorkField.tsx` + `work/ProjectPreview.tsx`): a split composition — an editorial index lower-left, a living per-project preview center/right — sitting inside the shared pointer-field engine (`WorkField`). Projects rest in the noise register and resolve to the accent on hover/focus/keyboard (roving arrow keys, focus-selects); opening is a separate explicit `Enter` action so a touch tap selects first and never opens by accident. Each project has its own abstract, concept-built preview composition (OS windows / editorial page / focused rooms / writing path) rather than a fake screenshot.
- Project world (`shell/ProjectWorld.tsx`): reuses the `HeroField` engine verbatim, rasterizing the **project name** so the field literally re-forms into the project; a strong hero statement, problem → solution → outcome narrative, technologies, architecture highlights, and **qualitative-only** results (no fabricated metrics — a code-level TODO slot marks where real figures go), plus optional secondary "Visit live ↗" / "View source ↗" actions. The world is a single no-scroll screen like the rest of the shell — a condensed stack on mobile (title, statement, actions, a tight problem/solution/outcome, tech) that opens into a split at `lg` with the full detail column (adding architecture + results) beside the title; Escape and a "Back to work" both exit; focus moves into the world on open and returns to the entered row on close.
- Per-project accent identity (`projects.ts` `ProjectAccent`, `[light, dark]` channels): entering a world overrides `--lab-signal*` on that root only, retinting the resolving field and every accent below it into the project's own color (RicardoOS ships a cool cyan/teal). Home and the Work index keep the one canonical signal, so signal scarcity holds outside a world. On the Work index the override is scoped to the single active row + its preview.
- Shared-element morph: `layoutId={project-title-<id>}` links each index card title to its world hero title so it physically travels on enter/exit; the world's mask rebuilds once the morph settles so the field re-forms cleanly against the final heading box. Gated on reduced motion (plain crossfade). New `work.world` label block + per-project `world` narrative content across EN/ES/FR.
- `HeroField` touch upgrade: touch devices now get a live field too — the headline rests resolved (a phone visitor who never touches still sees the finished word) and a dragging finger sculpts the ambient field, with the loop parked until the first drag so idle phones pay nothing. Only `prefers-reduced-motion` is fully static now.
- Sound layer (feature `6`): a procedural Web Audio UI-feedback system with no audio asset files and no runtime dependency. `src/lib/sound.ts` synthesizes a small family of short, quiet blips (menu open/close, state navigation, toggle) from oscillators + gain envelopes, lazily creating a single `AudioContext` on the first play within a user gesture. Sound is off by default and opt-in via a new `SoundToggle` corner control (`src/components/ui/SoundToggle.tsx`) beside the theme/language toggles — a speaker on/off icon driven by a `data-sound` attribute for a flash-free first paint, with the preference persisted the same way as the theme (pre-hydration `SOUND_INIT_SCRIPT` + `useSyncExternalStore`). The blips are wired centrally through `ShellProvider` (menu + navigation) and the theme/language toggles, so every `playSound` is a no-op while sound is off and the site stays silent unless a visitor opts in. Enabling plays one soft confirmation; disabling is silent. New `sound.enable`/`sound.disable` copy across EN/ES/FR. No ambient bed, no hover sounds, no full-screen sound gate.
- No-scroll full-screen shell (feature `5`): the site is now a fixed, single-viewport interface that never scrolls, inspired by `pacomepertant.com`. Content lives in full-screen *states* (Home / Work / About / Contact) swapped via a menu rather than stacked down a scrolling page. A `ShellProvider` (`src/components/shell/`) holds the state machine (active view + menu open/close); `ShellStage` crossfades between states; only the Home (hero) state is built — `work`/`about`/`contact` render a noise-register `PlaceholderState` until their states land in later features. The existing `Work`/`About`/`Contact` section components are parked (kept, no longer rendered) for reuse as those states.
- Persistent corner navigation (`ShellNav.tsx`): the menu is gone — there is no `Menu` button, overlay, drawer, or hamburger. Four fixed corner actions are always visible and part of the Signal / Noise composition rather than floating utility buttons: the Dynamic Frame logo top-left (Home), Work top-right, About bottom-left, Contact bottom-right. Each is an editorial icon + concise label with a generous invisible target (≥44×44), a subtle active state (`aria-current="page"` plus a short signal accent line and the icon's central point resolving to signal — never color alone), and fast, precise hover/focus motion (fragments align, the label sharpens and nudges a few pixels); activating a corner emits one short controlled pulse (<500 ms) and morphs the central field into that state. Custom SVG glyphs (`shell/nav/icons.tsx`) — Dynamic Frame, a Work constellation, an About coordinate-orbit, a Contact transmission — all decorative (`aria-hidden`) since a visible label or `aria-label` names each control. The `<nav>` spans the viewport but is `pointer-events-none` so it never intercepts pointer/touch meant for the field; a corner tap always wins. Offsets come from safe-area-aware `--shell-inset-*` variables (no control flush to the edge, no clipping, no horizontal overflow). The same corner system carries to mobile — icon-only at ≤400 px with the label kept in the accessibility tree and revealed on tap/focus, safe-area insets respected, `touch-action: manipulation`. `Escape` collapses an open project world, else returns to Home. New shell corner CSS (`.shell-corner*`, activation-pulse keyframes) replacing the old `.shell-wordmark`/`.shell-control`/`.shell-menu-link` classes; nav labels translate across EN/ES/FR (Work/Proyectos/Projets, About/Acerca de/À propos, Contact/Contacto/Contact) with a translated `nav.primary` landmark name. The language switch updates the corner labels live. Removed the old `ShellMenu` overlay, all `menu*` shell state, and the `nav.menu`/`nav.close`/`nav.openMenu`/`nav.closeMenu` strings.
- Signal / Noise hero (feature `4`): the pointer-field engine now carries the headline. The `<h1>` is real DOM text sitting in the noise register (`--lab-noise-4`, always legible, indexable, first to paint); a canvas layer above it rasterizes the same text to a coverage mask (`HeroField.tsx`) so the fragments inside the letterforms resolve into a signal-colored fill under the pointer, sharpening the word out of scatter and letting it drain back behind the cursor. The word is never *revealed* by the field — DOM owns legibility, canvas owns resolution, and they are registered against each other. Coarse pointers and `prefers-reduced-motion` render the whole word resolved as one static frame with no loop, so a phone visitor still sees the finished headline; the field never blocks scrolling. Left-aligned editorial composition, new copy ("Noise becomes structure."), and a ghost CTA so the resolved headline is the single signal accent in the view.
- Glyph field in the engine (`src/lib/pointer-field.ts`): a `GlyphMask` type with a pure coverage sampler, a second finer fragment population (`glyph*` tuning) laid only over the headline ink and tagged `inGlyph`, and a `resolveWordStatically` helper for the static frame. Ambient fragments now cap at the brightest noise step and never take the accent, so the assembled word is the only accent-colored thing on screen.
- Pointer-field prototype (feature `3`): the Signal / Noise signature interaction, built as a Canvas 2D engine (`src/lib/pointer-field.ts`) plus a thin client wrapper. A field of short line segments rests in noise; the pointer creates a temporary radius of local order in which fragments rotate into alignment, lengthen, and take the `--lab-signal` accent, then decay back roughly three times slower than they resolved so the trailing edge lingers. Fragments never translate — orientation, length, width, and color carry the whole effect, which is what keeps it from reading as a particle trail. Colors are read from the CSS custom properties at runtime, so both themes work with no per-theme tuning. Frame-rate independent, DPR-aware, and the loop idles to zero scheduled frames once the field settles. `prefers-reduced-motion` renders one composed static frame and never starts the loop. All tuning lives in a single documented `DEFAULT_TUNING` object; the throwaway tuning page it was found on was removed when Feature 4 landed.
- Signal / Noise design foundation (feature `2`): a palette where color carries the concept — a near-neutral base, a four-step noise ramp (`--lab-noise-1` … `--lab-noise-4`) for unresolved states, and exactly one `--lab-signal` accent reserved for resolved states (alignment, focus, active, CTA). Every token defined in both themes at introduction, no deferred theme pass.
- Named, fluid type scale (`display`, `h1`, `h2`, `h3`, `body`, `small`, `label`), each step carrying its own size, leading, and tracking as tokens. Added Instrument Serif via `next/font/google` as the display face (`h1`/`h2`/`.lab-display`), with Geist Sans on `h3`/prose/UI and Geist Mono promoted to a deliberate label role (`.lab-label`, eyebrows, kickers, tokens).
- Shared motion vocabulary: duration tokens (`fast`, `base`, `slow`, `field`) and easing tokens, principally the signature `resolve` curve — quick to leave, long to settle. Exposed as CSS custom properties and as a typed module (`src/lib/motion.ts`) so CSS and the `motion` library share one source of truth.

- Holographic HUD panel system for the Process section (feature 47): a reusable `ProcessHudPanel` (`src/components/sections/process/ProcessHudPanel.tsx`) rendered as a DOM/CSS glass overlay layered over the WebGL canvas — thin glowing token-driven border frame, corner ticks, mono/technical type, step + title header, translated status indicator, metric rows, and a small deterministic SVG sparkline. Extended `src/data/process.ts` with an illustrative per-stage `hud.sparkline` waveform and added matching `process.hud` copy (shared labels + per-stage status/metrics, illustrative values only) to `en.ts`/`es.ts`/`fr.ts`. Unified the existing per-stage copy crossfade in `ProcessScrollRig` and the mobile `MobileProcessStage` onto the panel; all accents flow from the per-stage `--stage-signal` cyan/teal token and the scan shimmer self-disables under `prefers-reduced-motion`.
- Premium 3D rendering foundation for the Process section (feature 45): a shared material toolkit (`src/components/sections/process/processMaterials.tsx`) exporting transmission `GlassMaterial`, `BrushedMetalMaterial`, and `EmissiveCoreMaterial`, plus a fetch-free generated studio `ProcessEnvironment` (static-export safe — no HDRI URL), a `ProcessBench` (`MeshReflectorMaterial`), and a restrained bloom+vignette `ProcessEffects` composer. Added `@react-three/postprocessing`.

### Changed

- The Home corner now shows the **"Lamadrid Labs" wordmark stacked under the Dynamic-Frame mark** (top-left corner set to a column) instead of being icon-only, and every corner is named by its always-visible label, so the icon-only-Home / hover-revealed-label behavior is retired.
- Made the Work index and project worlds genuinely no-scroll on mobile so a finger drag sculpts the field instead of scrolling the page. `WorkState` and `ProjectWorld` dropped their internal `overflow-y-auto` for `overflow-hidden` and now fit a single viewport at every size: the Work index hides the decorative preview on mobile (keeping the heading, index, and live statement, vertically centered) and restores it at `lg`; the project world condenses to a stack on mobile (problem/solution/outcome bodies clamp so nothing clips) and opens into a title-beside-details split at `lg`, so a project's info sits *next to* the title rather than below a scroll. Blocks in the world render plainly instead of via `whileInView` (a scroll-triggered reveal would strand lower blocks at opacity 0 with no scroll). `WorkField` got the same touch-live upgrade `HeroField` already had — a coarse pointer now drives the field on drag (loop parked at rest) rather than rendering a frozen frame.
- Converted the app shell to the no-scroll interface (feature `5`): `layout.tsx`'s body is now `h-svh overflow-hidden` with a `ShellProvider` + `ShellNav` + a single full-viewport `main`, and `page.tsx` renders only `ShellStage` instead of a stack of scrolling sections. Retired the fixed floating-pill `Nav` and the IntersectionObserver scroll-spy it depended on (there is no scroll to observe); active state is now the shell's current view. `navigation.ts` moved from href anchors (`navLinks`) to typed view keys (`navItems` / `ViewKey`).

- Wired the existing motion call sites (`MotionPrimitives`, `Nav`'s mobile menu) to the shared vocabulary, replacing three hardcoded easing arrays and four ad-hoc durations.
